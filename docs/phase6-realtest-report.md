## 4. 发现的问题与修复

### 4.1 findById 返回类型不匹配
- **问题**: 测试脚本将 `findById` 返回值当作 `AttachmentInfo | null` 处理，实际返回 `Result<AttachmentInfo, ErrorCode>`
- **修复**: 改用 `found.ok` 和 `found.value.originalName` 访问

### 4.2 计算器浮点精度
- **问题**: `1,234.56 + 5,678.90` 结果为 `6913.459999999999` 而非 `6913.46`
- **修复**: 测试中使用 `Math.round(result * 100) / 100` 进行四舍五入

### 4.3 百分比语义
- **问题**: `100%` 在表达式引擎中被转换为 `1`，所以 `(150-120)/120*100%` 结果为 `0.25`
- **修复**: 更正测试预期值为 `0.25`

### 4.4 FileEditTool API 不匹配
- **问题**: 测试脚本使用了不存在的 "read" 操作，且 replace 参数名错误 (`content`/`find` → `oldString`/`newString`)
- **修复**: 使用 `fs.readFile` 代替 read 操作，修正 replace 参数名

### 4.5 WebFetchTool API 不匹配
- **问题**: 测试脚本调用 `webFetch.execute({url, maxLength})`，实际 API 为 `webFetch.fetch(url, maxChars)`
- **修复**: 改用正确的 `fetch` 方法和参数

### 4.6 Windows 保留策略目录残留
- **问题**: Windows 上 `fs.rm` 可能无法完全删除包含文件的目录
- **修复**: 测试中增加逐文件删除 + `fs.rmdir` 的清理逻辑
