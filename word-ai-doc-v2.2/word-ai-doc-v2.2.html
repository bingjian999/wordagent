3.1 数据模型与存储引擎

保留原 AttachmentInfo 接口定义及 AttachmentStore 实现。关键点：

并发安全修正： 原文档声称"Node.js 单线程模型，await 间不中断，无需锁"。此论断部分错误，已修正为以下两层模型：
层次安全模型说明
内存 Store
(Map 操作)		单线程保护 ✓JavaScript 同步代码段不中断，Map.set() / Map.get() 操作原子。无需锁。
文件 I/O
(fs 操作)		需原子操作await 是中断点，其他异步操作可在两个 await 之间插入。文件操作需使用"临时文件 + 原子重命名"模式。

文件 I/O 原子写入模式：

// 正确：临时文件 + 原子重命名
async function safeWriteFile(targetPath: string, data: Buffer): Promise<void> {
    const tmpPath = targetPath + '.tmp.' + crypto.randomUUID();
    await fs.writeFile(tmpPath, data);        // 写入临时文件
    await fs.rename(tmpPath, targetPath);     // 原子重命名
}

// 错误：存在 TOCTOU 竞态
async function unsafeWrite(targetPath: string, data: Buffer) {
    const exists = await fs.access(targetPath);  // ← 中断点 A
    if (!exists) {
        await fs.writeFile(targetPath, data);      // ← 中断点 B，另一请求可能已写入
    }
}
  • 安全防护： sanitize() 防路径遍历；ALLOWED_EXTENSIONS 白名单（通过配置读取）；50MB 双重限制（通过配置读取）
  • 预览生成： tryPreview() 检测不可打印字符比例，防止二进制伪装
  • 数据保留： 每个 session 创建时记录时间戳；实现定期清理任务（默认保留 7 天，可通过 WORD_AI_SESSION_TTL 配置）；在 session_shutdown 事件中可选清理

工具注册示例（Pi Agent 官方模式）

import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";
import { Type } from "typebox";

export default function (pi: ExtensionAPI) {
    pi.registerTool({
        name: "file_read",
        label: "Read File",
        description: "Read content from an uploaded attachment",
        parameters: Type.Object({
            attachmentId: Type.String({ description: "Attachment ID to read" }),
        }),
        async execute(toolCallId, params, signal, onUpdate, ctx) {
            // 通过 ctx.sessionManager 获取会话标识
            const sessionId = ctx.sessionManager.getSessionFile();
            const result = await attachmentService.readText(sessionId, params.attachmentId);
            if (!result.ok) {
                return { content: [{ type: "text", text: `Error: ${result.error}` }], details: {} };
            }
            return {
                content: [{ type: "text", text: result.text }],
                details: { encoding: result.encoding, size: result.size }
            };
        },
    });
}

5.2 Shell 沙箱化方案 EXPANDED

P1 修正 — Shell 排期从 1 天扩展至 2 天（Day 10-11）。 原方案的"命令白名单"无法防止参数注入（如 ls; rm -rf /）。

沙箱化架构：

// src/services/shell/CommandRegistry.ts
interface CommandSpec {
    name: string;
    args: ArgSpec[];           // 参数模式定义
    allowGlob?: boolean;       // 是否允许通配符
    timeout?: number;          // 命令级超时
}

interface ArgSpec {
    pattern: RegExp;           // 参数正则
    required: boolean;
    description: string;
}

// 白名单命令注册
const COMMANDS: Record<string, CommandSpec> = {
    'ls':    { name: 'ls',    args: [{ pattern: /^[\w./-]+$/, required: false, description: 'path' }] },
    'cat':   { name: 'cat',   args: [{ pattern: /^[\w./-]+$/, required: true,  description: 'file' }] },
    'grep':  { name: 'grep',  args: [
        { pattern: /^[\w]+$/,        required: true,  description: 'pattern' },
        { pattern: /^[\w./-]+$/,     required: true,  description: 'file' }
    ]},
    // ... 更多命令
};

// 执行器 — 使用 execFile 而非 exec，避免 shell 解析
async function executeCommand(
    cmd: string, args: string[], opts: { cwd: string; timeout: number }
): Promise<ShellResult> {
    // 1. 验证命令在白名单中
    const spec = COMMANDS[cmd];
    if (!spec) return { ok: false, error: `Command '${cmd}' not allowed` };

    // 2. 验证每个参数匹配模式
    for (let i = 0; i < args.length; i++) {
        const argSpec = spec.args[i];
        if (!argSpec || !argSpec.pattern.test(args[i])) {
            return { ok: false, error: `Argument '${args[i]}' not allowed for '${cmd}'` };
        }
    }

    // 3. 使用 execFile 执行（不经过 shell，无注入风险）
    const controller = new AbortController();
    const timer = setTimeout(() => controller.abort(), opts.timeout);

    try {
        const { stdout, stderr } = await execFile(cmd, args, {
            cwd: opts.cwd,           // 锁定工作目录
            signal: controller.signal,
            maxBuffer: 1024 * 1024,  // 1MB 输出限制
            timeout: opts.timeout,
        });
        return { ok: true, stdout, stderr };
    } finally {
        clearTimeout(timer);
    }
}

关键安全措施：

  • 使用 child_process.execFile 而非 exec — 避免 shell 字符串解析，杜绝命令注入
  • 参数级白名单 — 每个参数通过正则验证，而非仅验证命令名
  • AbortController + 超时（默认 30s，可配置）

Extension 生命周期管理示例 NEW

import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function (pi: ExtensionAPI) {
    let services: ReturnType<typeof createServices> | null = null;
    let httpServer: import('http').Server | null = null;

    // ✓ 正确：在 session_start 中初始化资源
    pi.on("session_start", async (_event, ctx) => {
        const config = loadConfig();
        services = createServices(config);

        // 启动 HTTP 服务器
        httpServer = startHttpServer(services, config);
        ctx.ui.notify("Attachment platform ready", "info");
    });

    // ✓ 正确：在 session_shutdown 中清理资源
    pi.on("session_shutdown", async (_event, _ctx) => {
        if (httpServer) {
            await new Promise<void>(resolve => httpServer!.close(() => resolve()));
            httpServer = null;
        }
        // 清理临时文件
        if (services) {
            await services.attachmentService.cleanupTempFiles();
            services = null;
        }
    });

    // ✗ 错误：不要在 factory 中启动后台资源
    // httpServer = startHttpServer(...)  // ← 不可！
}
